# Codex Native Agents

native-only 的目标是由主程自行选择更合适的执行方式，而不是每个任务都启动子代理。
在用户已经授权的开发范围内，主程可以自行拆分与并发；明确的“先别改”“不要子代理”
等要求优先。安装与运行环境权限不会因自动调度扩大。

| 任务情况 | 执行方式 |
| --- | --- |
| 小修改、上下文不明确、文件紧密耦合 | 主程直接完成 |
| 独立调查、边界清楚的模块实现，主程还有其他工作 | 原生子代理 |
| 多个独立任务，依赖已满足且读写不冲突 | 按可用名额并发 |
| 共用索引、锁文件、生成产物，或依赖尚未完成 | 串行，由明确负责人整合 |

统一使用 gpt-6-astra：简单调查 low、常规实现 medium、复杂实现/审查 high、
关键判断和最终验证 xhigh。复杂调查提升到 medium。模型/强度不受宿主支持时回到主程，
不静默改用 GPT-5.6。一次失败可提高一档重试；第二次失败回主程诊断，不无限派工。

普通开发默认 standard：主程审查实际差异，执行相关检查并验证源码仍然对应结果。
高风险或用户明确要求独立审查时选择 strict：需求审查、质量审查、最终验证依次建立
准确的运行绑定。审查和最终快照在派工前固定，晚到的旧报告不能验收新实现。

宿主有 close_agent 时保存真实关闭结果；没有时读取原始终态日志，记录
closeStatus=unsupported。中断不等于关闭。登记结果会核对实际模型、思考强度、完整
最终报告、身份和终态；缺少证据不能标为成功。空工作流不能通过验收。

本地离线测试只能证明调度/证据规则，不能证明模型效果或生产性能。
