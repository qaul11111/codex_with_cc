# Codex Native Agents

native-only 的目标是由主程自行选择更合适的执行方式，而不是每个任务都启动子代理。
在用户已经授权的开发范围内，主程可以自行拆分与并发；明确的“先别改”“不要子代理”
等要求优先。安装与运行环境权限不会因自动调度扩大。

较大的开发或调查任务必须先评估：当前任务的多代理模式、可独立派出的工作、
主程同时要做的工作，以及派工与验收成本。在大量执行前简短说明拆分和模型，
或说明具体不派工原因；符合条件就完成预检并派工，不能只说“可以拆分”。
范围扩大、阻塞情况或模式变化后重新评估。小修复不需要工作流或固定格式说明。

| 当前模式/约束 | 规则 |
| --- | --- |
| 允许主动多代理 | 按收益和独立性评估后派工 |
| 仅允许用户、AGENTS 或适用技能明确要求 | 本技能明确要求派出符合条件的独立任务，满足此模式的条件 |
| 宿主完全禁止，或用户要求不用子代理/串行 | 遵守限制，由主程执行并说明具体原因 |
| 模式不明、工具或模型不可用 | 核实当前指令/能力，说明阻碍，不猜测可派工 |

启动和每轮提示钩子都会提醒主程评估，普通开发请求也适用，不依赖“派工”关键词。
子代理只收到执行职责提示。插件不会修改任务的多代理模式；提醒和技能属于指令约束，
不能保证模型每次都遵循，也不是后台强制调度器。`advise` 可记录模式与明确的原因码，
输入由主程根据当前指令填写，不能把它的建议当作宿主授权。

| 任务情况 | 执行方式 |
| --- | --- |
| 小修改、上下文不明确、文件紧密耦合 | 主程直接完成 |
| 独立调查、边界清楚的模块实现，主程还有其他工作 | 原生子代理 |
| 多个独立任务，依赖已满足且读写不冲突 | 按可用名额并发 |
| 共用索引、锁文件、生成产物，或依赖尚未完成 | 串行，由明确负责人整合 |

按任务、复杂度、风险和当前宿主能力选择模型：

| 档位 | 模型 / 思考强度 | 适用工作 |
| --- | --- | --- |
| economy | gpt-6-luna / low | 聚焦、边界明确的轻量工作 |
| balanced | gpt-6-sol / medium | 常规开发与分析 |
| balancedHigh | gpt-6-sol / high | 需要深入推理的开发与审查 |
| frontier | gpt-6-astra / xhigh | 复杂判断、高风险任务、最终验证 |

主程判断角色和复杂度，运行时自动选择可用档位，并保存首选、实际选择和原因。
默认路由不可用时只向更强的受支持档位寻找；没有合适档位则回主程。
`--model-profile` 是明确固定档位，不因不可用或失败而偷偷改模型。
宿主必须公布精确 model ID 和思考强度，不能把 GPT-5.6 Sol/Luna 当成 GPT-6。

自动任务首次失败后可升级一次：Luna → Sol，Sol → Astra；Astra 已到顶，
无更高档位则回主程。升级重新准备并保留之前的执行证据，每个任务最多两次尝试。
缺失输入、权限和工具故障先解决原因，不靠更贵模型重复尝试。

`route` 命令可在派工前预览实际选择。主会话保持用户选择的模型；本插件为子任务
选择模型，不会自行切换正在运行的主会话。工作流是主程调用原生工具完成的，
不是后台独立调度服务，也不按三个模型平均分配任务。

普通开发默认 standard：主程审查实际差异，执行相关检查并验证源码仍然对应结果。
高风险或用户明确要求独立审查时选择 strict：需求审查、质量审查、最终验证依次建立
准确的运行绑定。审查和最终快照在派工前固定，晚到的旧报告不能验收新实现。

宿主有 close_agent 时保存真实关闭结果；没有时读取原始终态日志，记录
closeStatus=unsupported。中断不等于关闭。登记结果会核对实际模型、思考强度、完整
最终报告、身份和终态；缺少证据不能标为成功。空工作流不能通过验收。

性能收益需要真实相近任务对比：关注总耗时、结果质量、返工和所有层的 token 用量。
本地离线测试只能证明调度/证据规则，不能证明模型效果或生产性能。

截至 2026-09-23，[官方模型目录](https://developers.openai.com/api/docs/models)
列出的每百万 token 标准输入/输出价为 Astra $10/$50、Sol $2/$10、Luna $0.1/$0.5。
这些单价不是整项任务费用；重试、上下文传递、缓存、服务档位和中转渠道计费都会影响结果。
